# Enochian multiplayer client

The existing local game and canonical engine remain unchanged outside the four named insertion blocks: `ENOCHIAN_MULTIPLAYER_UI`, `ENOCHIAN_MULTIPLAYER_CONTROLS`, `ENOCHIAN_CLIENT_SDKS` and `ENOCHIAN_MULTIPLAYER_CLIENT`. The new block wraps local input/session functions. Local mode calls the original functions; multiplayer stops the local CPU lifecycle and sends intent commands instead of applying local moves. Changing back to local play leaves the room, clears online callbacks and restores the local color selection. Launcher visibility handling remains in the protected local lifecycle. Page exit closes the transport without an intentional Leave command.

`window.ENOCHIAN_MULTIPLAYER_CONFIG = { endpoint: '' }` leaves online creation unavailable and preserves offline local play. Staging may configure an HTTPS endpoint. Loopback HTTP is accepted for development only; a development address control appears only when `allowCustomEndpoint: true` is explicitly configured. No backend addresses or private credentials are hardcoded.

The approved official browser bundles `@colyseus/sdk@0.18.4` and `@supabase/supabase-js@2.117.2` are embedded inline with source SHA-256 hashes and MIT license text for bundled package dependencies. No runtime CDN is used. `node scripts/embed-client-sdks.mjs` regenerates the dedicated vendor block; `--check` verifies deterministic contents and pinned package versions. Script-end sequences are safely escaped, and original vendor literal whitespace is preserved. The server's generated engine remains extracted from the protected canonical block.

Private creation/join uses POST `/invitations` or `/invitations/join` with name, chosen color, mode and optional room code. The response supplies stable match ID, current transport ID, public invitation code, authenticated color and a private seat credential. The credential is retained only in the protocol core's memory, never a share URL, public projection or browser storage. Invite links contain only `invite=<public code>`; manual code entry works when wrappers discard URL parameters. Private-room SDK admission uses `joinById(roomId, { credential, authorization? })`.

Every ready/color/move/exchange command carries exactly `matchId`, `requestId`, `expectedRevision`, `protocolVersion: 1`, `rulesVersion: 'enochian-current-1'` and `action`. Lobby actions are `{type:'ready',ready}` or `{type:'color',color}`. Move actions are `{type:'move',fr,fc,tr,tc}`. Exchange actions are `{type:'offer',counterpart}` or `{type:'accept'|'reject',offerId}`. Only one command is pending at a time. Sending never mutates the board. Committed Schema patches or acknowledgement snapshots advance the displayed state monotonically; older revisions and callbacks from a previous session are ignored. Rejections remain visible in the feedback line. A delayed confirmation disables new commands until recovery obtains committed state.

The public projection allowlists board pieces, alive flags, seat display/control/readiness/connectivity, phase, turn, revision, deadlines and terminal result. It removes ownership IDs, auth UUIDs, credentials and unknown fields. Schema maps and HTTP snapshots share this projection. Available colors are constrained by the current roster. The server's public exchange eligibility hint (`exchangeAvailable[color]` or the Schema seat's `exchangeCounterpart`) supplies the only offer candidate; only the intended connected human counterpart sees Accept/Reject. Ranked remains disabled unless the server's public configuration explicitly enables it after its release gates.

Transport auto-reconnection is disabled in favor of application recovery: POST `/invitations/recover` with stable match ID and the original private credential returns the new transport route and authenticated color. A final HTTP snapshot displays the terminal result without reopening play. Lost color-change acknowledgements are repaired by the authenticated returned color. Casual accepted bot moves remain final, and the original owner can reclaim only during the server's remaining cumulative 180-second allowance. Ranked displays the immediate paused state and cannot issue moves or exchange actions until the server resumes it. Service recovery uses the public grace deadline.

Account configuration comes from GET `/identity/config`. Sign-in opens a separate top-level page through a five-minute handoff: POST `/identity/handoffs` returns a handoff ID, private poll/completion secrets and expiry. `/signin#handoff=<id>&complete=<secret>` handles provider sign-in outside the embedded game. The game polls POST `/identity/handoffs/consume` with the poll secret; a completed one-time response supplies the bearer authorization privately. If automatic return fails, the separate sign-in tab displays a manual return code that can be redeemed in the game. A popup-blocked link remains available. No bearer token is put in a URL or sent through cross-frame messages. The game retains authorization only in memory and discards it on explicit sign-out. The configured project currently enables email, with social providers disabled; provider setup and live email testing are outside this change. Platform accounts are not automatically linked.

`node --test tests/enochian-multiplayer-client.test.mjs` runs the protocol harness with a fake SDK and transport, plus insertion/engine-byte and SDK generation checks. It tests public projection, intent-only moves, pending/rejection state, monotonically committed snapshots, color acknowledgement/recovery races, stale sessions, dropped connections, terminal recovery, paused commands and backend unavailability. Real browser/two-device/runtime deployment acceptance belongs to the integration phase.
